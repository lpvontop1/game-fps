===============================================================
  DEKOMPOSISI PROMPT — GAME FPS 3D BERBASIS WEB
===============================================================

Deskripsi: File ini memecah prompt game FPS 3D berbasis web yang
besar dan kompleks menjadi tahapan-tahapan kecil yang berurutan.
Setiap tahap adalah sub-prompt mandiri yang dapat diberikan kepada
AI agentic satu per satu. Setiap tahap BERTUMPU pada hasil tahap
sebelumnya, jadi urutan harus diikuti secara strict.

Struktur file:
- Bagian A: Daftar semua tahapan (overview)
- Bagian B: Sub-prompt lengkap per tahapan (siap salin-tempel)

---------------------------------------------------------------
TAHAP 01 — Fondasi Proyek & Scene 3D
---------------------------------------------------------------
Buat fondasi game FPS 3D berbasis web menggunakan Three.js.

Output: 4 file dasar — index.html, style.css, script.js, item.json

Ketentuan:
- index.html memuat Three.js via CDN, memuat style.css & script.js
- style.css: fullscreen canvas tanpa margin, cursor crosshair, font monospace untuk UI
- script.js: init scene Three.js, camera (PerspectiveCamera), renderer (WebGLRenderer), resize handler, render loop
- item.json: untuk sekarang isi dengan skeleton kosong: { "weapons": [], "armor": [], "loot": [] }
- Camera posisi awal: y=1.7 (tinggi manusia), z=5
- Scene: background warna abu-abu muda (#CCCCCC), 1 ground plane (PlaneGeometry besar, warna #555555)
- Tidak ada gameplay logic di tahap ini, hanya scene yang render-able

---------------------------------------------------------------
TAHAP 02 — Kontrol Pemain: Berjalan (WASD)
---------------------------------------------------------------
Tambahkan kontrol berjalan pemain FPS menggunakan WASD ke scene yang sudah ada dari tahap 01.

Ketentuan:
- W = maju, A = kiri, S = mundur, D = kanan (relative ke arah kamera)
- Kecepatan berjalan: 5 unit/second
- Gunakan velocity-based movement (smooth, bukan snap)
- Kamera adalah pemain — posisi kamera = posisi pemain
- Input handling: keydown/keyup, simpan state di object keys{}
- Update posisi kamera di render loop berdasarkan keys state
- Pemain tetap di y=1.7 (tinggi berdiri), tidak bisa naik/turun secara vertical untuk sekarang
- Pastikan movement relatif ke arah camera look (buat forward/right vector dari camera quaternion)

---------------------------------------------------------------
TAHAP 03 — Mekanik Lompat (Jump)
---------------------------------------------------------------
Tambahkan mekanik lompat (jump) ke pemain yang sudah bisa berjalan dari tahap 02.

Ketentuan:
- Tombol Space = lompat
- Fisika: gravity -9.8 unit/s² (world downward = -Y)
- Pemain punya vertical velocity (velocityY)
- Saat Space & pemain di ground: velocityY = jumpForce (coba 5 unit/s)
- Setiap frame: velocityY += gravity * deltaTime; position.y += velocityY * deltaTime
- Ground level = 1.7 (tinggi berdiri). Saat position.y <= 1.7: pemain di ground, velocityY = 0
- Pemain tidak bisa lompat lagi saat di udara (isGrounded flag)
- Smooth: tidak ada jitter saat landing
- Tambahkan visual indicator kecil di HUD (opsional: "GROUNDED" / "AIRBORNE" text debug)

---------------------------------------------------------------
TAHAP 04 — Mekanik Lari (Sprint)
---------------------------------------------------------------
Tambahkan mekanik lari (sprint) ke pemain yang sudah bisa berjalan & lompat dari tahap 03.

Ketentuan:
- Tombol Shift (kiri) = sprint
- Sprint speed: 9 unit/s (walk speed tetap 5)
- Stamina system: stamina max 100, sprint mengurangi stamina 20/s, recovery 10/s saat tidak sprint
- Saat stamina = 0: pemain tidak bisa sprint, otomatis kembali ke walk speed
- Stamina bar ditampilkan di HUD (kecil, bottom-left)
- Sprint hanya bisa saat di ground (tidak bisa sprint di udara)
- Movement logic: jika Shift && isGrounded && stamina > 0 → speed = 9, else → speed = 5
- Stamina recovery juga saat pemain berdiri diam (tidak menekan WASD)

---------------------------------------------------------------
TAHAP 05 — Mekanik Jongkok / Merayap (Crouch & Crawl)
---------------------------------------------------------------
Tambahkan mekanik jongkok (crouch) dan merayap (crawl) ke pemain dari tahap 04.

Ketentuan:
- Tombol C = toggle crouch (bukan hold, tapi toggle)
- Crouch: kamera turun dari y=1.7 ke y=0.9, speed = 3 unit/s (lebih lambat)
- Crawl: jika crouch + tekan C lagi (atau Ctrl) → kamera turun ke y=0.4, speed = 2 unit/s
- Crouch/crawl: pemain tidak bisa lompat
- Untuk berdiri kembali: tekan C toggle off → smooth transisi kamera kembali ke y=1.7 (lerp, bukan snap)
- Transisi smooth: interpolasi position.y antara state (standing ↔ crouch ↔ crawl) dengan lerp factor 0.1 per frame
- Crouch/crawl bisa sprint? Tidak. Sprint hanya saat standing.

---------------------------------------------------------------
TAHAP 06 — Mouse Look / Kamera FPS Pertama
---------------------------------------------------------------
Tambahkan kontrol kamera FPS (mouse look) ke pemain dari tahap 05.

Ketentuan:
- Pointer Lock API: klik canvas → lock pointer, ESC → unlock
- Mouse movement: deltaX = yaw (horizontal rotation), deltaY = pitch (vertical rotation)
- Sensitivitas mouse: 0.002 radian per pixel (default, bisa diubah di settings nanti)
- Yaw: rotasi kamera di Y-axis (camera.rotation.y atau euler y)
- Pitch: rotasi di local X-axis, clamp antara -89° dan +89° (tidak bisa lihat lebih dari vertical)
- WASD movement harus relatif ke arah yaw (forward = arah kamera, bukan world Z)
- Crosshair ditampilkan di tengah canvas (CSS: position fixed, small dot or plus sign)
- Mouse look harus smooth, tidak ada jitter

---------------------------------------------------------------
TAHAP 07 — Collision Detection Dasar
---------------------------------------------------------------
Tambahkan collision detection agar pemain tidak bisa menembus dinding/objek di scene dari tahap 06.

Ketentuan:
- Implementasi: ray-based collision atau AABB collision
- Pemain punya bounding box (radius 0.5, height sesuai state: 1.7/0.9/0.4)
- Sebelum update posisi, cek apakah posisi baru akan overlap dengan obstacle
- Obstacle: semua mesh di scene yang memiliki tag "collidable" (userData.collidable = true)
- Jika collision: pemain slide (keep component yang tidak collide, blok component yang collide)
- Ground plane tidak collidable (pemain bisa berjalan di atas)
- Tambahkan 2-3 box obstacle ke scene untuk testing (dinding box, warna #888888)
- Visual: pemain tidak bisa menembus dinding, berjalan mengikuti permukaan dinding (wall slide)

---------------------------------------------------------------
TAHAP 08 — Map/Arena Minimalis Pertama
---------------------------------------------------------------
Buat map/arena game minimalis maze-like untuk scene dari tahap 07.

Ketentuan:
- Map: maze-like arena, bukan pure maze. Campuran: area terbuka + corridor + ruangan
- Ukuran: kira-kira 50x50 unit
- Material: hanya warna solid (MeshStandardMaterial tanpa texture), warna-warna abu-abu & krem
- Dinding: BoxGeometry, height 3 unit, thickness 0.5
- Floor: satu plane besar, warna #555555
- Semua mesh collidable (userData.collidable = true)
- Layout: buat secara procedural atau manual, minimal ada:
  - 1 area terbuka besar di tengah (open arena ~15x15)
  - 4 corridor menghubungkan area terbuka
  - 3-4 ruangan kecil (~5x5) di corners
  - 2 choke point (narrow passage ~2 unit wide)
- Lighting: ambient light + 1 directional light (sun-like, slight shadow)
- Tidak ada texture yang memberatkan performa

- Contoh: glock damage 20, pemain total defense 40 → effective = 20-40 = clamped to 1
- Sniper bolt 90 damage vs defense 40 → effective = 50
- Headshot multiplier: 2x damage (raycast hit ke area head entity)
- HP bar: tampilkan di HUD (bar merah hijau, top-left)
- Death: saat HP <= 0, trigger death event (untuk sekarang: pemain respawn di spawn point setelah 3s)
- Damage flash: screen flash merah 0.2s saat hit
- Heal: tidak ada heal mechanic untuk sekarang (mungkin ditambah nanti)
